# Development and release procedures

These procedures keep builds repeatable and distinguish a local debug build from a user ready release.

## Prepare a checkout

```sh
git clone --recurse-submodules https://github.com/mmorrone90/firemirror.git
cd firemirror
git submodule status --recursive
```

Use JDK 17 and Android SDK Platform 36. The receiver also uses NDK `27.0.12077973` and CMake. Accept SDK and NDK licenses in Android SDK Manager before building.

## Build and verify

Build each app and run the same checks used by GitHub Actions:

```sh
./gradlew :app:assembleDebug :app:lintDebug
./gradlew :phone:testDebugUnitTest :phone:lintDebug
./scripts/build-phone.sh
./scripts/build-receiver.sh
export ANDROID_HOME="$HOME/Library/Android/sdk"
cd receiver
./gradlew :app:testDebugUnitTest
cd ..
```

If Android Studio stores the SDK elsewhere, set `ANDROID_HOME` to that folder before running the receiver test.

The output APKs are under `dist/`. They are debug signed. Do not describe them as production signed releases. A release signing key is not stored in this repository.

Before sharing a build, check the actual package version, signature, and APK contents with Android SDK tools:

```sh
aapt dump badging dist/EmberCast-receiver-debug.apk
apksigner verify --verbose dist/EmberCast-receiver-debug.apk
aapt dump badging dist/EmberCast-phone-debug.apk
apksigner verify --verbose dist/EmberCast-phone-debug.apk
```

## Test on devices

Use [installation instructions](INSTALL.md) to install on a Fire TV and Android phone. Test at least:

1. Receiver opens and its advertised name is visible on the TV.
2. Mac discovers EmberCast and a normal desktop image appears.
3. Android phone is discovered or can connect by address, gets TV approval, and shows live video.
4. Stop sharing ends the session. Supported app audio plays on TV and the phone volume is restored.
5. Rotation, network interruption, screenshot, recording, and connection approval behave as expected for the change.
6. No credentials, home network addresses, private screenshots, or personal recordings are present in logs or issue attachments.

Record the model, Fire OS version, Android API, app version, network type, and exact steps. Mark an untested result as untested rather than inferring compatibility.

## Change the receiver

`receiver/` is a pinned upstream Git submodule. EmberCast receiver changes are carried in `patches/receiver-firemirror.patch`, which the build script applies after initializing the submodules. The patch must apply to the revision named in `git submodule status`. Preserve upstream attribution and license notices. Keep the local banner backup out of the patch and out of commits.

To check that the patch is already applied in a development checkout:

```sh
git -C receiver apply --reverse --check ../patches/receiver-firemirror.patch
```

To test it from a clean checkout, clone with submodules and run `./scripts/build-receiver.sh`. Do not update the receiver or its nested UxPlay, FFmpeg, libplist, or OpenSSL submodule revisions without reviewing compatibility, security fixes, and every affected license.

## Change artwork

The original EmberCast Fire TV artwork is generated by `artwork/render_embercast_assets.swift`. After editing it, run:

```sh
swift artwork/render_embercast_assets.swift .
```

Inspect the generated PNGs at their actual dimensions. Keep the square launcher icon, landscape TV banner, and Appstore artwork as separate assets. The Tabler SVGs in `docs/assets/icons/` are third party assets; follow their MIT notice if modifying or redistributing them.

## Prepare a GitHub change

1. Use a focused branch and keep unrelated assets out of the change.
2. Run the builds, unit tests, lint, and device checks that apply.
3. Review `git diff --check`, `git status`, the license notices, and the final files.
4. Open a pull request with the tested device details and any remaining limits.
5. Do not attach APKs signed with a personal debug key. A signed public release needs a deliberate signing and key storage plan.

## Publish a release

The public repository currently has no signed release APK. Before publishing one, choose a stable release signing method, store signing credentials only in protected GitHub Actions secrets or an equivalent secure system, and verify that the same key can sign future updates. Never commit a keystore, passwords, private certificates, or local SDK paths. Publish source, attribution notices, and matching installation instructions with the release.
